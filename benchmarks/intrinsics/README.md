# Intrinsic library benchmarks

Nine small programs that exercise the intrinsic libraries ([docs/intrinsics.md](../../docs/intrinsics.md)) on real-app workloads. Each runs on every lane, and the results lines must match.

| App | Library | Workload |
|---|---|---|
| `hash` | int | xxHash32, CRC-32 (4 MiB) and xxHash64 (64 KiB, bigint) over generated text |
| `qoi` | int | QOI image encode and decode, 512×512 RGBA |
| `lz4` | int | LZ4 block compress and decompress, 2 MiB of text |
| `bitset` | int | sieve to 4 million, popcount, set-bit iteration, intersections |
| `physics` | math | 320 discs, 400 frames, swirl, drag, collisions; state hashed by bits |
| `snapshot` | layout | world-snapshot delta codec, 2000 entities, 300 ticks, packet sizes |
| `particles` | layout | 20000 particles written in place into a 32-byte GPU vertex layout |
| `f16-mesh` | f16 | a 160000-vertex mesh packed to binary16 and back |
| `blur` | atomics | a tiled box blur as a job system: bands claimed from an atomic counter |

Each app has `baseline.ts`, the work in plain TypeScript, and `main.ts`, the same work with the library. The lanes are:

- `js`: `node baseline.ts`;
- `js+fallback`: `node main.ts`, the libraries' plain-JavaScript bodies;
- `wasmgc-base` and `wasmgc`: both compiled to WasmGC (release) and run under Node;
- `native-base` and `native`: both compiled with the LLVM backend for this machine.

Two apps add lanes in `lanes.mjs`. `f16-mesh` runs the package's engine entry. `blur` runs four worker threads over shared memory, and the task ring's owner-thread drain.

Inputs are generated inside each program (`common/input.ts`), so every lane reads the same bytes and no data files are needed. The layout apps' view classes are generated by the layout library: `node snapshot/gen.mjs` and `node particles/gen.mjs` rewrite `entity.gen.ts` and `vertex.gen.ts`.

```console
$ node benchmarks/intrinsics/run.mjs            # every app; writes receipts/<app>.json
$ node benchmarks/intrinsics/run.mjs hash --no-native
$ node benchmarks/intrinsics/results.mjs        # RESULTS.md from the receipts
```

The harness needs a built workspace (`pnpm -r build`). The native lanes also need the LLVM helper and the runtime pack built for the machine (AGENTS.md: the `@scriptc/llvm-<platform>` and `@scriptc/runtime-<platform>` `build:native` scripts).
