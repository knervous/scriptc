# Edits on top of the reference port

These are the edits made to the converted port (React 19.2.8 in TypeScript, PROVENANCE.md) for the WasmGC builds of the React table benchmark (benchmarks/react-dom), on top of the hand edits that brought the conversion to strict TypeScript.

- `react-reconciler/src/ReactCapturedValue.ts`: `createCapturedValueFromError` takes `unknown` (its one caller is the dehydrated-boundary path in `ReactFiberBeginWork`). The compiler refuses a compiled `Error` as a weak-map key, because an `Error` entering a dynamic slot is a snapshot, not the same reference. Client rendering never reaches this function.
- `react/src/ReactMemo.ts`: `memo` takes `type: unknown`. `React.ElementType` includes an abstract constructor type, which the compiler cannot lower as a record field.
- `react-dom-bindings/src/events/getListener.ts`: an absent handler prop (`undefined`) is returned as `null`. The cast to `EventHandler | null` is checked in compiled code, and every caller tests `!= null`.
- **The DOM bridge** (`packages/dom-stream`): React DOM's host instances are the bridge's compiled nodes, and their changes are written to the DOM stream and replayed by the page once per commit.
  - `ReactFiberConfigDOM`: `Instance`, `TextInstance`, `Container` and the boundary instances are bridge types. The hot paths (create, append, insert, remove, text, properties, styles, hide and unhide, clear) write to the stream. `prepareForCommit` and `resetAfterCommit` bracket the commit with `beginCommit` and `endCommit`, where the page notes and restores the focus and selection itself, and `resetAfterCommit` flushes.
  - Rare paths materialize their node with `page()`, a sync point that flushes the stream, and run React DOM's own DOM code on the page's node: view transitions, measurements, test selectors, focus, observers, fragment instances, singletons, the script element trick, and form elements (`ReactDOMInput`, `ReactDOMSelect`, `ReactDOMTextarea` and option `selected`, whose state is the page's).
  - Resources keep the page's elements (`TResource.instance: Element`), found and inserted in the page's head. Their initial properties go through the bridge, flushed before insertion (`setInitialPropertiesOnPage`). A resource's fiber state node is the adopted bridge node.
  - Hydration is not supported over the bridge. `hydrateRoot` throws, and every hydration-only host function throws the same refusal.
  - `ReactDOMComponentTree`: a bridge node holds its internals record itself. A page node (an event target, a form, `relatedTarget`) is looked up as the bridge node at or above it, one call into the page's node table.
  - Events still arrive as page events through the root listeners. `event.currentTarget` is the page's node, and a root container matches the page element it was adopted from.
- `react-reconciler/src/ReactFiberConfigWithNoPersistence.ts`: the persistence shims that stand for an instance are typed as returning one (a call typed `never` lowers as a number in compiled code).
- `react-reconciler`: state node reads followed by a null test are typed `| null` (`detachFiberAfterEffects`, the host update in `commitMutationEffectsOnFiber`, `ReactFiberApplyGesture`'s text instances). With a compiled `Instance`, a non-null type is a checked cast.
- Event listeners: React's root and per-element listeners register through the stream (`dom-stream`'s `listen`), and the page forwards each event with one call. `createEventListenerWrapperWithPriority` returns a closure over its arguments instead of a bound function: binding a compiled function goes through the page, and would make each listener a page function.
- `ReactFiberTreeContext`: the fork and id stacks are typed (`Array<Fiber | number | null>`, `Array<Fiber | number | string | null>`) and each pop casts to its slot's type, `getInstanceFromScope` (DOM config) answers `Fiber | null`, and `ReactTestSelectors` reads `current` through `FiberRoot`. Untyped values cast into `Fiber` gave the type a record arm next to `FiberNode`, so every fiber field read tested both forms.
- `ReactJSXElement.createElement`: skips the `defaultProps` read for a string (host) type. A member read on a string primitive is the page's (`String.prototype`), so it cost two host calls per host element; only component types carry `defaultProps`.
- `ReactElementType`: an element's fields are typed (`$$typeof: unknown`, `type: unknown`, `key: string | null`, `ref: unknown`, `props: Record<string, unknown>`) and the production-absent `_debugInfo` is left out, so the one literal that builds elements (`ReactJSXElement.ReactElement`) is exactly that record type. With `any` fields an element lowered as an untyped object, so every `element.type` / `.props` / `.key` read went through dynamic dispatch. `ReactChildFiber` casts at its few uses that relied on `any` (the ref, fragment children, a lazy element type).
